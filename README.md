# supplier-scout

Сервис поиска поставщиков продуктов питания и упаковки для ресторанов: условия поставщика сведены в одну форму, у каждого поля — источник и статус, формула подсказывает, кому написать первым и что спросить.

> **Набор в `data/suppliers.json` собран конвейером 13.10.2026.** Екатеринбург, 4 категории, 60 реальных поставщиков и ещё 2 для экрана «Добавить по сайту или ИНН». У каждого значения — источник: цитата со страницы сайта или запись реестра. Отчёт прогона лежит в `data/runs/2026-10-13.json`: что отсеяно и почему, полнота по полям, расход. Генератор демо-фикстуры прототипа (`data/fixture/`) пишет в тот же файл и затирает настоящий набор. Публиковать фикстуру нельзя: `node scripts/check-data.mjs --release` на ней завершится ошибкой.

## Запуск

На Windows — двойной клик по `dev.bat`: при первом запуске поставит зависимости, поднимет сервер и откроет браузер.

Вручную:

```bash
cd web
npm install
npm run dev        # http://localhost:5173
npm run build      # статическая сборка в web/dist (маршруты через #, открывается с GitHub Pages)
```

## Конвейер сбора данных

`pipeline/` на Python 3.12 собирает `data/suppliers.json`. Зависимости — httpx, lxml, pypdf и openpyxl.

```bash
pip install -r requirements.txt
python -m pipeline.selftest                 # правила проверки цитат, ИНН, часов, ассортимента, robots.txt — без сети и без модели
python -m pipeline.run --budget-rub 100     # весь сбор; потолок — на расход этого прогона; отчёт — data/runs/<дата>.json
python -m pipeline.run --offline            # пересборка из кэша: без модели и без сайтов, ключ Kie не нужен
```

`--offline` не вызывает модель и не открывает сайты — только кэш в `pipeline/.cache/`. Реестры по ИНН бесплатны, поэтому и в этом режиме запросы, которые в прошлый раз не прошли (капча ФНС), повторяются. Отчёт второго прогона за день пишется рядом (`<дата>-2.json`), прошлый не затирается.

| Шаг | Что делает | Чем |
|---|---|---|
| 1. Кандидаты | веб-поиск по подкатегориям и городу; карты, каталоги, маркетплейсы и соцсети отсеиваются по домену | `--provider gemini` — Gemini с поиском Google через Kie, ссылки только из источников поиска; `--provider seed` — выдача поиска, записанная в `data/seed/` |
| 2. Фильтр | по главной странице: поставщик, агрегатор, розница, ресторан или статья | Claude Haiku 5.5 через Kie, пачками по 10 сайтов |
| 3. Сайт | главная и до пяти страниц: контакты, доставка, реквизиты, опт, прайс; robots.txt по RFC 9309 (не открылся — сайт закрыт для сбора); PDF и XLSX-прайсы; сайты на JS — через Jina Reader, но только если страница отдалась без текста: после отказа сервера (403, 429) посредника не зовём | httpx, lxml |
| 4. Поля | модель возвращает значение, дословную цитату и номер страницы; код ищет цитату в тексте страницы и сверяет с ней значение: числа, слова адреса и условий, «работает с ресторанами», да/нет в доставке, единицу минимума; телефоны и почту — с текстом, ИНН — по контрольной сумме; что не прошло — отбрасывается | Claude Haiku 5.5 |
| 4б. Ассортимент | корень каталога и до 7 разделов меню, до 2 прайс-листов; прайс в xlsx разбирает код по шапке таблицы, страницы каталога и PDF — модель, а код оставляет только позиции, которые дословно стоят на странице, и цену — только рядом с названием. В карточке до 150 позиций: столько хватает показать, чем торгует поставщик, и найти его по товару, а набор целиком грузится в браузер | Claude Haiku 5.5, openpyxl |
| 4в. Часы | режим работы, до скольки принимают заказ, дни и окно доставки, возят ли после 20:00 — фразы со страниц сайта, разобранные шаблонами | без модели |
| 5. Проверка по ИНН | статус, возраст, ОКВЭД, выручка, численность, налоговый режим, флаги · декларации · маркировка · банкротство | ФНС «Прозрачный бизнес», Росаккредитация, «Честный знак», Федресурс — бесплатно, кэш на неделю |
| 6. Оценки ◇ | пустой минимальный заказ — медиана известных в категории; цены «по запросу» — разброс открытых цен по эталонным товарам | только из проверенных цитатами значений |
| 7. Запись | `data/suppliers.json` по контракту `web/src/types.ts` и отчёт прогона: сколько отсеяно и почему, полнота по полям, расход | — |

### Один поставщик по сайту или ИНН

Тот же код, что у пакетного сбора, но для одной компании: сайт задан явно, поиск и фильтр по главной не нужны.

```bash
python -m pipeline.one --site molluska.ru            # сайт → страницы → поля с цитатами → ИНН → реестры → карточка
python -m pipeline.one --inn 6678050810 --category grocery   # только ИНН: реестры ФНС, Росаккредитации, «Честного знака», Федресурса
python -m pipeline.one --site example.ru --into-set  # дописать карточку в набор как live_only (для экрана «Добавить»)
```

Карточка пишется в `data/live/<хост или ИНН>.json`, набор `data/suppliers.json` без `--into-set` не меняется. `--category` переопределяет категорию, для «только ИНН» он обязателен. Если модель решила, что сайт не поставщик, карточка получает `not_supplier` с причиной. Если ИНН на сайте не совпал с заданным, расхождение выводится в консоли и записывается в `meta.inn_conflict`. Расход одного сайта — около 0,3 ₽, повтор по тому же сайту берёт кэш и стоит 0 ₽.

```
[+0:52]    страниц 4, полей 13, отброшено цитатами 0 · потрачено 34.90 ₽
[+0:52]    категория: Рыба и морепродукты
[+0:52] 3/4 Реестры по ИНН 6679179246: ФНС, Росаккредитация, «Честный знак», Федресурс
Карточка: Моллюска — Рыба и морепродукты
  Юрлицо          ООО "НА ВОЛНЕ" [found]
  ИНН             6679179246 [claimed]
  Адрес           Екатеринбург, Красноармейская ул., 92А — магазин [claimed]
  Доставка        до двери [claimed]
  Компания в ФНС  ООО, active, с 2024-10-28 [found]
```

Ключ Kie — переменная окружения `KIE_API_KEY` или строка `KIE_API_KEY=…` в файле `~/.claude/secrets/supplier-scout.env` (путь меняется переменной `SUPPLIER_SCOUT_ENV`). В репозитории ключей нет; ключ читается при первом платном вызове, поэтому `--offline` и `--until candidates` работают без него. Каждый вызов модели пишется в журнал расхода. `--budget-rub` — потолок на этот прогон: на каждый вызов, который уже ушёл в одном из трёх потоков, держится резерв, чтобы параллельные вызовы не перешли потолок. Вызов, на который за 180 с не пришёл ответ, не повторяется — модель могла отработать и списать деньги; сайт соберётся в следующем прогоне.

Промежуточные результаты лежат в `pipeline/.cache/`, в git они не попадают. Повторный запуск берёт их оттуда: правка правил проверки и сборки не стоит денег и не нагружает сайты. Раскладка сайта моделью годна 30 дней; запись «сайт не открылся» не кэшируется — временный сбой не оставит поставщика несобранным навсегда.

Сколько страниц открывается на одном сайте за прогон: поля — главная и до 5 страниц, добор ИНН — до 3 страниц реквизитов, оферты и политики, ассортимент — до 8 страниц каталога и 2 прайс-листа. Всего не больше 19 загрузок на сайт, это общий счётчик в `pipeline/fetch.py`.

Персональные данные. У индивидуального предпринимателя в набор идёт «ИП Фамилия И. О.»: ИНН физлица, полное ФИО и мобильные номера в карточку не попадают, цитаты с полным ФИО снимаются, ссылка на страницу-источник остаётся. По ИНН конвейер проверяет реестры, но в набор его не пишет. `node scripts/check-data.mjs --release` падает, если в `data/` нашёлся ИНН физлица, полное ФИО или мобильный ИП.

## Устройство

```
data/
  suppliers.json         # набор по контракту web/src/types.ts: поле = значение + статус + источник + цитата
  fixture/               # генератор демо-фикстуры (node data/fixture/build-fixture.mjs)
web/src/
  types.ts               # контракт данных
  lib/score.ts           # рекомендация: стоп-условия, 6 критериев, веса по «что важнее»
  lib/explain.ts         # текст «почему» и черновик письма — шаблоном из полей, без модели
  screens/               # поиск, результаты, карточка, сравнение, разбор балла, шорт-лист, добавить, как собраны данные
scripts/
  e2e.cjs                # приёмочный прогон сценариев кликами в headless Chromium + скриншоты 390/1440
  check-data.mjs         # проверка набора перед публикацией
  prepare_illustrations.py  # иллюстрации категорий: обрезка по объекту, равная площадь
```

Статусы полей различаются формой знака, а не цветом: ● найдено в реестре · ◐ со слов поставщика · ○ не найдено · ◇ оценка по рынку · ✎ вручную.

Шорт-лист, заметки и статусы контакта хранятся в браузере (localStorage), без входа.
